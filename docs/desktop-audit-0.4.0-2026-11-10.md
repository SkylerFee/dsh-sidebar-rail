## 需要处理的问题

### 功能问题：添加项目未完成，且成功目录值被丢弃

**真机证据**：插件添加入口超时；宿主原生入口可弹选择器。两者不能合并为「native picker 已验证通过」。插件实际使用 `uiWorkspace.pickDirectory()`；宿主目录流还可以优先走 preload 的 `__DSH_DIRECTORY_PICKER__.pick()`。本轮没有从已发布 App 的 Host 日志中证明插件 Remote 后端为何没有返回，因此后端根因仍待定位。

**源码及受控探针证据**：`client.js:2221` 的 `.then((picked) => undefined, (error) => error)` 丢弃了成功路径。将原回调提取执行，目录选择替身返回合法绝对路径，状态为 `busy → idle`，但 **`createWorkspace` 调用次数为 0**。即便解决真机选择器不返回的问题，当前成功分支仍无法登记项目。

**时间预算边界**：`client.js:2196` 在打开选择器前就启动 5s 计时，因此人工选择耗时也在预算内。这是源码事实；本轮没有完成「插件原生选择器打开后人工等待超过 5s」的复现，不扩大真机结论。

### 功能问题：默认收起的任务分区需要点两次

`client.js:1875` 的 `toggleSection` 对尚不存在的键总写入 `true`，含义是已收起；它未将该区的默认收起状态纳入第一次切换。真机「已暂停」为 **收起 → 首次仍收起 → 第二次展开**；原回调探针得到相同序列 **false → false → true**。对「已结束」的影响属于同一实现推断，本轮没有再做原生双击复验。

### 轻微布局问题：浮层外框越过底边 2px

`client.js:339` 的 `.dsr-flyout` 在本环境计算为 `box-sizing:content-box`，有上下各 1px 边框。脚本写入的 `height=901px=949−48` 是内容高度；实测外框为 **903px**，因此 `top=48`、`bottom=951`。底部步进器仍可见和操作，本轮没有观察到主要操作被遮挡，但外框未精确贴合视口底边。
