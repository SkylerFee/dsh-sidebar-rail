# 0004 浮层改为「分区 + 固定标题 + 独立滚动」，并占满高度

- 状态：**部分被 [ADR-0007](0007-single-scroll-flyout.md) 取代**（2026-11-10）。本 ADR 的「分区独立滚动」「每区 1/3 限高」「标题固定」三件事已被撤销；「浮层占满可用高度、高度不随内容与条数变化」继续有效。以下为当时的历史记录，不删。
- 相关：`client.js` `flyoutShell` / `workspaceFlyoutHeight` / `.dsr-pane` 系列样式

## 背景

0.3.x 的工作区浮层是「两个等分 pane」：项目区在上、最近会话区在下，各占一半高度，浮层高度固定为视口 70%（`WORKSPACE_FLYOUT_VIEWPORT_RATIO = 0.7`）。

0.4.0 要在浮层里塞进更多结构：工作区三分区、每项目可展开会话、任务三分区、插件两分区。两 pane 的形态撑不住这些：

- 三分区需要三个独立滚动区，两个 pane 的布局模型不适用。
- 70% 高度在分区变多后显得局促，而内容确实需要更长。
- 用户明确要求「每个分区标题行不随内容滚动」——这决定了标题与内容必须分层。

## 决定

1. **浮层占满可用高度**：顶部从 `--dsh-frame-top-clearance`（48px）之下开始，底部到窗口底。不再用视口比例。
   - 不覆盖顶部 48px 带：那里有 macOS 红绿灯与宿主挂在 `shell.leading` 的重开/新会话控件（AGENTS.md 硬约束 3）。
2. **分区 = 固定标题行 + 独立滚动内容区**：`.dsr-pane` 内部再拆 `.dsr-pane-head`（`flex:none`）与 `.dsr-pane-scroll`（`overflow-y:auto`）。
3. **三个工作区分区各占「三等分」为最大高度**：每个分区的高度上限是可用高度的 1/3，内容超出后该区自己滚动；内容不足 1/3 时不强行撑满。
   - 这样三个区在视觉上大致均衡，又不会因为某一区只有一行而在底部留出大片空白。
4. **分区之间用 `--dsw-alias-border-l1` 画分隔线**。

## 后果

- 浮层高度不再随内容变化，也不再随 `recentCount` 变化（0.3.2 已解决的性质保持住了）。
- 分区的展开/收起只影响滚动位置与可见条目数，**不影响浮层总高度**。
- 窗口很矮（可用高度 < 三区最小可读高度）时，三区会互相挤压；当前不为此做额外降级，因为矮窗本就落在「视口 ≥ 768px 才渲染」的边缘。

## 不要做什么

不要改回「浮层高度随内容增长」。那会让浮层在切换分区时跳动，也让「最近会话条数」重新影响布局——这正是 0.3.2 修掉的缺陷。
