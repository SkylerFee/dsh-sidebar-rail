# 0009 浮层的滚动与高度：单一滚动容器，高度随锚点与内容

- 状态：已采纳（2026-11-13）
- 合并并取代：原 ADR-0004（分区 + 固定标题 + 独立滚动 + 1/3 限高 + 占满高度）、原 ADR-0007（单一滚动容器）、原 ADR-0008（高度随锚点与内容）——三篇原文已删除、编号不再复用，但其中的**历史判断与理由全部保留在本篇「演进史」**；原 ADR-0007 曾明确要求「不要删除 ADR-0004 的历史理由」，本条继承该约束。
- 相关：`src/client/components/flyout-shell.tsx` 的 `makeFlyoutShell`、`src/client/components/flyouts.tsx` 的 `shell()` 调用、`src/client/components/primitives.tsx` 的 `FlyoutSection`、`src/client/model/geometry.ts` 的 `flyoutPlacement` / `flyoutSectionedHeight`、`src/client/styles.css` 的 `.dsr-sections` / `.dsr-flyout-foot`

## 为什么合成一篇

这三篇是同一条推理链上的三次判断，指向**同一个对象**（浮层的内容区如何滚动、面板多高）。分开读时会出现「原 ADR-0004 说占满、原 ADR-0007 说保留、原 ADR-0008 说其实从未落地」的三段追认，读者要来回翻三份文件才能拼出当前形态。

合并后，一份文档同时回答三个问题：**现在是什么形态**、**它推翻过什么**、**哪些旧说法已经作废**。顺带消除了仓库里两篇 `0008` 的编号重复（`0008-github-release-security` 保持原号）。

## 演进史（原判断保留，不删）

### 0.3.x：两个等分 pane

工作区浮层是「两个 pane」：项目区在上、最近会话区在下，各占一半，浮层高度固定为视口 70%（`WORKSPACE_FLYOUT_VIEWPORT_RATIO = 0.7`）。

### 0.4.0 第一步：分区 + 固定标题 + 独立滚动 + 1/3 限高（原 ADR-0004）

0.4.0 要往浮层里塞更多结构：工作区三分区、每项目可展开会话、任务三分区、插件两分区。两 pane 的形态撑不住，于是改为：

1. 浮层**占满可用高度**：顶部从 `--dsh-frame-top-clearance`（48px）之下开始，底部到窗口底，不再用视口比例。
2. **分区 = 固定标题行 + 独立滚动内容区**（`.dsr-pane-head` + `.dsr-pane-scroll`）。
3. **每个分区的高度上限是可用高度的 1/3**，内容超出则本区自己滚动。
4. 分区之间用 `--dsw-alias-border-l1` 画分隔线。

当时的理由是三个分区内容长短不一，各自限高加独立滚动能让它们视觉上大致均衡，且不让某个长列表撑满整块面板。

### 0.4.0 第二步：收敛为单一滚动容器（原 ADR-0007）

上述结构在真机上暴露两个问题：

1. **列表被切碎**。同一浮层里并存多个滚动区，指针落错区域就滚错地方。
2. **与宿主习惯相反**。宿主侧栏与实测的 Codex 侧栏都是**一个整体滚动区**：分组只是标题，分隔靠留白，滚动时整页一起动、标题跟着滚走。三段式横线 + 三个滚动条读起来像「三块表格」。

于是显式反转（原 ADR-0007 特意留了记录，怕后人把这次简化当回归）：内容区改为**单一滚动容器**，删除分区之间的分隔线，删除 1/3 限高（`sectionMaxHeight` / `sectionBudgetFor` / `SECTION_HEIGHT_RATIO` 一并删除，不留空壳），**分区标题随内容滚动**（放弃「标题固定」，这是本次最直接的取舍）。分区仍可折叠，收起时内容卸载，折叠状态不持久化。

### 0.4.0 第三步：高度这条其实从未落地（原 ADR-0008）

原 ADR-0007 声明「保留原 ADR-0004 的另一半：浮层高度钉死为 chrome 带之下到底边」。2026-11-11 的真机实测证明这条**从 TypeScript 迁移那天起就没生效**：

- 0.4.0 的 `client.js` 确实给三个分区浮层传了第七个参数 `topFlush = true`；
- TS 迁移（`0ae88d3`）把调用改写成 6 个参数，**漏掉末尾的 `topFlush`**；
- 于是 `makeFlyoutShell` 一直走 `flyoutPlacement` 的锚点分支，高度取锚点以下的剩余空间且不写内联 `height`。

实测数据：任务浮层从 y≈98 开始，展开两个空态分区后底边从 y≈371 变到 y≈491；工作区顶边约 58px、插件顶边约 138px，都跟着图标锚点走。

**处理方式是改决定而不是改代码**：承认当前形态更贴近宿主（浮层跟着触发它的图标走是弹层的一般预期），且让五个浮层行为一致（账号与「更多」浮层本来就高度随内容）。真正造成跳变的从来不是「高度随内容」，而是**分区各自的滚动与限高**——那已经被上一步删掉了。

## 当前决定

### 1. 滚动：一个浮层只有一个滚动容器

分区的标题与条目都在 `.dsr-sections` 这一个 `overflow-y:auto` 的流里。分区（`.dsr-section`）只是「标题行 + 条目组」，**不是滚动单元，也没有高度上限**。分区之间不画分隔线，分组靠标题字重与留白区分。

`.dsr-sections` 是浮层里**唯一**允许拥有 `overflow-y` 的元素（`.dsr-flyout-body` 只服务于非分区浮层）。滚动条由内容是否超出面板自然出现，因此不会为空槽预留位置。

### 2. 高度：跟随锚点与内容，不强行占满

- **按触发图标的位置摆放**：`flyoutPlacement` 用图标矩形算出上边或下边偏移，`maxHeight` 取该位置以下的剩余空间。
- **高度随内容**：不写内联 `height`，面板由内容撑开，受 `maxHeight` 封顶。
- **不覆盖顶部 chrome 带**：仍以 `FLYOUT_EDGE_GAP` 与锚点矩形为界，不会压到 macOS 红绿灯与宿主挂在 `shell.leading` 的重开 / 新会话控件。

账号浮层底边对齐；「更多」浮层同理——五个浮层共用同一套定位语义，不再有「三个分区浮层被强行拉满」的特例。

### 3. 分区折叠与底栏

分区可折叠，收起时**卸载**内容（保留挂载会让下次展开回到旧滚动位置）。折叠只让内容变短：在跨过 `maxHeight` 边界之前面板外框不动。

`foot`（`.dsr-flyout-foot`，`flex:none` + 上边框）是**可选**的固定底栏，不参与滚动。当前只有任务浮层与插件浮层用它放「打开面板」；工作区浮层不传 `foot`。

## 后果

- 浮层里只有一个滚动条，滚动行为与宿主侧栏一致；长列表的分区标题会滚出视野，这是自觉的取舍。
- 短浮层（任务、插件）内容少时明显矮于整屏，下方留白是真实高度差异，不是渲染缺陷。
- 「分页不影响浮层高度」仍成立，但成立方式变了：不是靠固定高度，而是靠 `maxHeight` 封顶 + 整体滚动——条目增减只改变滚动内容。
- `topFlush` 与 `flyoutSectionedHeight` 保留在代码里但**三个分区浮层不再使用**；将来若要恢复全高，传 `topFlush = true` 即可，无需改 `flyout-shell`。
- 验收口径：不再要求「浮层底边贴窗口底」，改为要求「不覆盖顶部 chrome 带、不越出窗口、内容超出时内部滚动」。
- `geometry.ts` 只剩浮层定位与轨唤出判据；对着已删的限高能力写的断言一并删除。

## 已作废的旧说法（合并时核对代码后修正）

以下两句在原文与周边文档里流传过，**与当前实现不符**，在此明确作废：

1. **「最近会话条数的步进器在固定底栏，滚到哪里都能找到」**（原 ADR-0007 后果节）。可调的 `recentCount` 偏好已在 0.5.1 整项移除，没有步进器；工作区浮层不传 `foot`；「显示更多」是列表末尾的一个普通条目，随内容一起滚动。
2. **「分区收起 / 展开不影响浮层总高度」**（原 ADR-0007 后果节）。在高度随内容的当前实现下，折叠会让面板变矮（除非内容仍撑满 `maxHeight`）。这句成立的前提是固定高度，已随第 3 步一并失效。

## 不要做什么

- **不要改回分区独立滚动，也不要给分区重新加限高。** 碎片化滚动是被真机实测否决的，不是被忘记的。
- **不要为了找回「标题常驻」而引入 sticky header。** 多段标题叠粘与宿主观感不同，实现复杂度也不成比例。
- **不要为了对齐旧 ADR 而补回 `topFlush`。** 那会把三个浮层拉满全高，与账号 /「更多」浮层的观感割裂。
- **不要删掉 `topFlush` 与 `flyoutSectionedHeight`。** 它们是「将来若要恢复全高」的唯一入口，删了就得重写定位逻辑。
- **不要把「高度随内容」理解成「高度无上限」。** `maxHeight` 必须始终按锚点与视口计算，否则短窗口下面板会溢出。
- **不要删掉本篇的「演进史」。** 它记录的是「两 pane → 三分区 → 单一滚动」这条链上每一步的正确取舍；只留结论会让下一个人把简化当成回归，把回归当成简化。
