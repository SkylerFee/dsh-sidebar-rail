## 需要处理的问题

1. **优先恢复 Desktop 折叠后的图标轨。** 这是悬浮导航、账号入口和相关键盘验收的共同前提。[设计说明](design.md)已有 Desktop 折叠列宽可能为零的限制，本次将该限制复现为真实用户路径失败；本次没有读取布局尺寸，不能把零列宽写成实测数值。
2. **修复当前深色主题下的文字颜色。** [client.js](../client.js) 多处颜色使用 `--dsw-alias-text-primary` 等变量及偏深的回退色。应核实目标 Desktop 的实际主题 token；本次未读取计算样式，变量失配只是待核实的原因，截图能够直接证明的是对比度不足。
3. **接通 Desktop 中可用的设置入口，并确认展开态需求范围。** 当前渲染的是缺少命令接口时的提示分支；原生工作区浏览器的搜索等能力在默认自绘布局中缺失，不能把布局相似认作完整保留原导航。
4. **修复相对时间的语言选择。** 纯函数的中英文测试均通过，但真实中文界面仍显示英文，需要核查 locale 快照与界面当前语言的连接。

## 后续查证修正（2026-11-04，修复阶段）

验收时把「设置入口不可点」记为契约缺失（`ctx.get('commands')` 在客户端不存在）。修复阶段的源码核对显示还有一层更严重的连带问题，本报告的原始记录保留，但结论以此处为准：

- 宿主的设置面板 `SettingsRoot` 是「侧栏底部触发器 + `createPortal` 弹窗」的**整体组件**，注册为 `sidebar.settings` 单槽的占用者；其 `settings.open` 快捷键处理函数只设置该组件内的 store 状态。
- 插件当时替换了整个 `sidebar` 槽，且因 `ui-sidebar` 已声明那组子槽而不能声明 `children`，因此从不渲染 `sidebar.settings`。结果是 `SettingsRoot` 永不挂载：**展开态不仅设置按钮只是提示文字，连 `⌘,` 快捷键也无法打开设置**。
- 客户端不存在任何公开的「打开设置」通道：`ctx.reflect.provide` 的服务只有 `modules / resources / layout / pluginNavigation / uiRenderer / documentPreviews / sidebarRightTabs / sidebarRight / userQuestionPanels`；`ctx.shortcuts` 只提供 register/edit/describe/recording，没有 execute。

因此该问题的修复不是「接通入口」，而是收窄插件职责：不再替换 `sidebar` 槽，展开态完全交还宿主（搜索、视图选项、添加工作区、设置座位、账号菜单全部恢复），插件只补 macOS 折叠态图标轨。详见 [验证记录](verify.md) 第 6 轮。
