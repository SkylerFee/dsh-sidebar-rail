# 0.5.0 需求：贴近宿主原生的浮层与交互修正

> 状态：**已实现**——#9 ADR-0007、#10 三个缺陷、#11 整体滚动、#12 项目行、#13 间距与视觉，五张票全部合并（HEAD 见 git log）。**真机验收见 [verify.md](verify.md)**；本文件描述的是实现约定与预期行为，实际结果以 verify.md 为准。
> 来源：2026-11-10 通过 CUA 实测 Codex（ChatGPT.app 的 Codex 模式）侧边栏，与本插件逐项对比后提出的 6 组调整
> 相关：[GLOSSARY.md](../GLOSSARY.md)、[ADR-0001](adr/0001-narrow-viewport-predicate.md)、[ADR-0004](adr/0004-sectioned-flyout.md)、[ADR-0005](adr/0005-host-public-api-boundary.md)、[spec-0.4.0](spec-0.4.0-sectioned-flyout.md)

## 1. 背景

0.4.0 的浮层采用「三分区 + 每区独立滚动 + 每区 1/3 限高」。这套结构在真机上让列表被切得很碎，且与宿主侧栏的观感差距明显：宿主侧栏（以及 Codex 的侧栏）是**一个整体滚动区**，分区只是分组标题，不分隔、不限高、不各自滚动。

同时，0.4.0 遗留了三个可复现缺陷，并有若干处与宿主原生的交互/视觉习惯不一致。

本规格把它们整理成可实施的需求，**目标是「看起来、用起来都像宿主自己的一部分」**，而不是继续强化插件自己的设计语言。

## 2. 本次要解决的问题

1. 分区被 1px 横线切开、各自限高 1/3、各自滚动——视觉碎片化，滚动时多个滚动条并存，与宿主「一个列表 + 分组标题」的习惯相反。
2. 项目展开状态每次重开浮层都重置——用户展开某个项目看会话，移开鼠标再回来就没了。
3. 项目行的展开/收起用的是自绘 chevron + 自定义按钮，宿主用的是 folder-open / folder-close 图标 + 整行点击切换。
4. 浮层内各区之间、标题与条目之间的间距是拍出来的，与宿主 --dsh-sidebar-* 变量体系不一致。
5. 三个交互/功能缺陷：
   - **浮层位置错乱**：轨正在滑入（160ms transition）时悬停图标，浮层按过渡中途的 getBoundingClientRect() 定位，因此偏位。
   - **幽灵会话行**：项目展开后出现一个与项目同名的会话节点，点开无内容——因为快照缺 byId 条目时仍产出一行 title: id。
   - **添加项目完全不可用**：成功的目录值被 .then 丢弃（K1），且 pickDirectory 拒绝时被当作通用失败。
6. 视觉未完全沿用宿主 token 与原生件（图标、圆角、行高、hover 底色）。

## 3. 用户故事

1. 作为日常使用者，我希望浮层里的列表是**一个连续的滚动区**，这样我滚动时不会在多块各自滚动的小窗里来回找位置。
2. 作为日常使用者，我希望分区标题下面**没有分隔横线**，这样分组读起来像宿主侧栏的分组，而不是被切开的三块表格。
3. 作为日常使用者，我希望某个分区内容很多时**整页一起滚动**，而不是只有那一块在动、其余卡住。
4. 作为日常使用者，我希望内容超过浮层可用高度时**才出现滚动条**，内容少的时候没有滚动条干扰。
5. 作为日常使用者，我希望把某个项目展开看会话后，**移开鼠标再回来，它还是展开的**，不用每次重新点。
6. 作为日常使用者，我希望项目行的展开/收起是**文件夹图标 + 整行点击**，和宿主侧栏、Codex 的操作方式一致。
7. 作为日常使用者，我希望展开/收起项目时**图标从「关闭的文件夹」变成「打开的文件夹」**，一眼看出状态。
8. 作为日常使用者，我希望浮层里各行之间的**间距看起来是均匀、成体系的**，而不是有的地方挤、有的地方空。
9. 作为日常使用者，我希望在轨滑入的动画过程中悬停图标时，浮层**出现在正确的位置**，不跳、不偏。
10. 作为日常使用者，我希望展开一个**没有会话**的项目时看到明确的空态文案，而不是一个点了没反应的假会话节点。
11. 作为日常使用者，我希望点「添加项目」能**真的弹出系统目录选择器**，选定后项目出现在列表里。
12. 作为日常使用者，我希望取消目录选择时**什么都不发生**（不报错、不留 loading）。
13. 作为日常使用者，我希望目录选择失败时看到**能照着做的提示**，而不是一直转圈或一句通用错误。
14. 作为日常使用者，我希望浮层里的**颜色、圆角、悬停底色、字体**与宿主侧栏一致，不像外挂。
15. 作为日常使用者，我希望浮层的**图标风格（文件夹、箭头、图钉、加号）与宿主原生图标一致**。
16. 作为键盘使用者，我希望分区标题仍可用键盘聚焦与切换，且收起后内容卸载。
17. 作为日常使用者，我希望最近会话区的条数步进器**仍在**，且调整后列表跟着变，但**浮层高度不跳**。
18. 作为使用深色/亮色主题的人，我希望两种主题下浮层都正确（全部走宿主 token）。
19. 作为重度使用者，我希望置顶项目、项目、最近会话的**顺序与分组规则不变**，这次只改呈现方式。
20. 作为维护者，我希望这次改完之后，**浮层与宿主侧栏共用同一套间距变量**，以后宿主调整时插件自动跟上。

## 4. 实施方案决策

### 4.1 移除分区限高、独立滚动与分隔线

- 删除 .dsr-section 的 max-height: 33.3333% 与独立 overflow，改为**整块内容一个滚动容器**。
- 删除 .dsr-section + .dsr-section { border-top: ... }。
- **删除 sectionMaxHeight / sectionBudgetFor / SECTION_HEIGHT_RATIO**：限高取消后不再有消费者。相关单测同步删除，不保留空壳。
- 浮层高度仍**钉死**为「chrome 带之下到底边」（ADR-0004 的这个性质保留：高度不随内容与条数变化）。
- 滚动条只在内容超出时出现（overflow-y: auto 的自然行为），不预留槽位。
- 分区标题**仍不随内容滚动**这个旧性质**放弃**：整页滚动意味着标题会滚走。这是本次的**刻意取舍**，与 ADR-0004 的「标题固定」相反——需要新 ADR 记录这次反转。
- **已确认**：接受标题随内容滚走，不做 sticky。理由是最贴近宿主原生（宿主侧栏就是一个整体滚动区）。

### 4.2 项目展开状态持久化

- expandedProjects 从组件 state 迁移到**持久化存储**，与 pinnedWorkspaceIds / recentCount 同一个 localStorage 键（dsh.sidebar-rail.v1）。
- 新增字段 expandedProjectIds: string[]（工作区 id 数组）。
- 打开浮层时从存储读取；切换时写回（合并语义，不覆盖置顶与条数）。
- **不持久化分区收起状态**：分区折叠仍每次重开重置（沿用 0.4.0 的决定）。
- 已删除/不存在的工作区 id 读取时忽略，不做清理写入（避免无谓写盘）。
- **已确认**：读取时忽略失效 id，不写回清理。

### 4.3 项目行改用宿主原生展开方式

- 收起态用**关闭的文件夹图标**，展开态换成**打开的文件夹图标**（对齐宿主 IconFolderCloseRegular / IconFolderOpenRegular 的语义）。
- 展开/收起由**整行点击**触发（取消「只有箭头是按钮」的做法）。
- 右侧的图钉与新建会话按钮保留，且**阻止冒泡**，不触发展开。
- 图标来源：本项目只能 require react / react-dom，**不能 import 宿主 @deepseek-ai/dsh-client-ui-primitives**。因此自绘 SVG，但**形状、尺寸、颜色变量与宿主对齐**。
- 需先核实宿主 folder 图标的实际 path 数据与尺寸，按视觉对齐重绘。

### 4.4 间距对齐宿主变量

- 浮层内采用宿主侧栏的间距体系：--dsh-sidebar-inline-padding: 8px、--dsh-sidebar-row-padding: 12px、--dsh-sidebar-label-gap: 6px、--dsh-sidebar-paint-inset: 3px。
- 行内起始内边距 = var(--dsh-sidebar-row-padding) - var(--dsh-sidebar-paint-inset)；行间距用 label-gap。
- 分区标题的左内边距、行高、条目间距按宿主 WorkspaceBrowser.module.css 的 .sectionHeader / .sectionLabel 规则取值。
- 这些变量由宿主侧栏根节点提供；**浮层是 portal 到 body 的，拿不到侧栏根的继承**，因此需在浮层根节点上**显式声明同名变量（取宿主同值）**，并注释来源。

### 4.5 三个缺陷修复

#### 4.5.1 浮层定位偏移

- 根因：scheduleOpen 在**事件发生时**（t=0）就调 getBoundingClientRect()，而轨的 transform: translateX(-100%) → translateX(0) 需要 **160ms** 过渡，浮层在 **120ms** 后打开。此时 rect 反映的是过渡中途位置，anchor.right 偏小，浮层贴得太左。
- 修法二选一（实施时定）：
  - **(a)** 在计时器**回调里**再取一次 rect（而非事件时）；或
  - **(b)** 定位基准改为**轨的固定几何**（左缘 + 轨宽 56），不依赖按钮的实时 rect。
- **已确认选 (b)**：锚点的语义本就该是「轨的位置」，而非「某个按钮此刻在哪」。这样也顺带解决轨在收回动画中打开浮层的同类偏移。
- 需补一条**流程测试**：模拟 rect 在 transition 中途与结束两种取值，断言浮层位置用稳定几何。

#### 4.5.2 幽灵会话行

- 根因：projectSessionRows 在 byId 缺该 id 时仍 rows.push({ id, title: id, ... })。当 sessionIds 包含快照里没有的 id（重命名/删除的一帧差），就产出一行「标题 = id」的假会话。标题与项目名相同，视觉上像项目自身的副本。
- 修法：**不产出任何假会话行**。缺摘要的成员直接丢弃，并在调试日志记一行（不带标题/路径）。
- **用户补充要求**：项目下确实没有会话时，**显示空态提示语**（沿用既有 empty.projectSessions 文案），而不是任何占位行。空态与假会话必须区分清楚。
- 影响：原测试 projectSessionRows: unknown members degrade to an id-only row **需改写**为「缺摘要的成员被丢弃」；另需补一条「空项目只显示空态、零行」的用例。这是**行为变更**，必须在 verify.md 记录。

#### 4.5.3 添加项目不可用

- 根因 A（K1）：成功值被 .then((_picked) => undefined, ...) 丢弃，导致永远走「取消」分支。
- 根因 B：错误处理把**所有**拒绝都当成「选择器不可用」，而宿主 pickDirectory 在用户取消时是 **resolve null**（不抛），真失败才抛。
- 修法：
  - 修正 promise 链，成功时**保留**路径。
  - 明确三态：resolve(string) → 成功；resolve(null) → 取消（静默）；reject → 失败（显示可照做的提示）。
  - 成功后的 createWorkspace(path) 失败单独处理（登记失败 ≠ 选择失败），给不同文案。
- 需补流程测试覆盖三态与「登记失败」。

### 4.6 视觉完全对齐宿主

- 颜色：只用 --dsw-alias-* / --dsw-specific-sidebar-* 宿主 token，不允许出现硬编码色值。
- 承载面色：浮层底色改用与宿主侧栏一致的 --dsw-specific-sidebar-fill（现状是 --dsw-alias-bg-overlay，看起来偏「弹窗」）。
- 行悬停：--dsw-alias-interactive-bg-hover；当前会话：同宿主侧栏的选中态。
- 圆角：--dsw-radius-md（宿主行用 md，不是 lg）。
- 阴影/边框：按宿主浮层的实际组合（需在真机取计算样式后落值）。
- 字体：font-size: 14px（宿主侧栏根字号），标题 11–12px 与宿主一致。
- **已确认验收口径**：肉眼一致 + 全部走宿主 token。机械检查禁止硬编码色值（纳入 scripts/check-source.mjs），真机截图对比由人工确认，不做像素级自动对比。

### 4.7 需要新建的 ADR

- **ADR-0007**：撤销 ADR-0004 的「分区独立滚动 + 每区 1/3 限高 + 标题固定」。记录反转理由：真机对比后，碎片化滚动体验劣于整体滚动；「像宿主」优先于「分区自洽」。
- ADR-0004 标注「部分被 ADR-0007 取代」，保留历史理由。

## 5. 测试决策

- **行为测试优先于实现测试**：测「滚动容器只有一个」「分区之间无边框」「展开状态跨重挂载保留」，不测具体 class 名或 DOM 层级。
- 受影响的现有单测：
  - sectionBudgetFor / sectionMaxHeight 相关用例**删除**（能力已移除）。
  - sectionIsOpen 的用例**保留**（分区折叠仍在）。
  - projectSessionRows: unknown members degrade to an id-only row **改写**为「缺摘要成员被丢弃」。
- 新增流程测试：
  - expandedProjectIds 的读写、合并写入不覆盖置顶/条数、跨「重开浮层」保留。
  - 目录选择三态（成功/取消/失败）+ 登记失败。
  - 浮层锚点用稳定几何（不随 transition 中途 rect 变化）。
- 保留既有 56 项行为断言中**仍然成立**的部分，逐个确认，不整体删除。
- 真机验收：本次改动几乎全是视觉与交互，**必须**在 macOS Desktop 真机逐项确认，不能只靠单测。

## 6. 不在范围内

- 不改分区顺序、分组规则、置顶语义、recentCount 语义。
- 不引入宿主 ui-primitives 依赖（运行时依赖必须保持为零）。
- 不接管展开态宿主侧栏，不替换 sidebar 槽。
- 不跟随 Codex 的「轨常驻可见」「悬停展开整栏」「项目 hover 卡片显示路径」这三项（与 ADR-0001 / 硬约束 4 冲突）。
- 不做项目右键菜单、编辑项目、探索入口。
- 不持久化分区收起状态。

## 8. 实现顺序建议

按「先修缺陷、再改结构、最后调视觉」推进，每步都能独立验收：

1. **修三个缺陷**（4.5）：定位偏移、幽灵行、添加项目。这三项用户可直接感知，且互不依赖。
2. **结构精简**（4.1）：移除限高/分隔线/独立滚动，改为整体滚动。同步删掉 sectionMaxHeight 一族与其单测。
3. **项目展开持久化**（4.2）+ **原生展开方式**（4.3）：两者都改项目行，一起做。
4. **间距与视觉对齐**（4.4、4.6）：最后统一调，避免反复改样式。
5. **文档收尾**：新增 ADR-0007、更新 ADR-0004 状态、更新 docs/design.md 与 GLOSSARY.md（「分区」词条需改，因为「独立滚动」不再是定义的一部分）。

## 10. 风险

- **移除限高是一次已记录的决策反转**（ADR-0004 → ADR-0007）。若不写明理由，未来会有人以为是回归。
- **整体滚动 + 标题滚走** 会让「最近会话」标题在长列表里滚出视野，用户可能找不到条数步进器。缓解：步进器在浮层底栏（固定不滚），不受影响。
- **项目展开持久化**会让重开浮层时自动展开多个项目，列表可能一开始就很长。可接受，因为这是用户自己的选择。
- **幽灵行改为丢弃**可能让真实会话在重命名的瞬间消失一帧。已在决策中接受。
